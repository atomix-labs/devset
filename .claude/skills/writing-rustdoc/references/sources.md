# Sources

What each external source contributes, which house rule it backs, and where the
house departs from it. Cite one of these, or an equally primary source, when a
doc makes an external claim; never cite from memory, and open the page before
linking it.

How to read them for this skill: the API Guidelines and RFC 1574 fix *which*
sections and links exist; the Microsoft guidelines fix *length*; the rustdoc and
clippy pages fix *what the build enforces*; the std dev guide fixes *examples
and backticks*; the three reference crates fix *voice*, and win where they
differ:

| source says                                                                                                            | house does                                                                                                                                 |
| ---------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------ |
| "write `Returns` instead of `Return`" (RFC 1574)                                                                       | third person indicative, yes; but a getter names the value (`Bytes the span holds.`) instead of opening with `Returns`                     |
| `# Example` for a single example (std dev guide)                                                                       | `# Examples` always (RFC 1574)                                                                                                             |
| section order `Examples, Errors, Panics, Safety` (M-CANONICAL-DOCS; RFC 1574 lists `Examples, Panics, Errors, Safety`) | `Safety · Errors · Panics · Examples`: the contract before the demonstration                                                               |
| a blank line after a heading (common rustdoc habit)                                                                    | none after `# Safety`/`# Errors`/`# Panics`/`# Examples`; either way after a crate-level heading, consistently within a crate              |
| examples on functions are mandatory (std dev guide)                                                                    | on public types and substantive public fns; not on trivial accessors or private items                                                      |
| `#[doc(inline)]` on own re-exports (M-DOC-INLINE)                                                                      | `pub use crate::…` at the root already lists items with their siblings; used only where a nested re-export would otherwise show as a block |
| README as crate docs (Linebender)                                                                                      | not done; `//!` is written directly                                                                                                        |
